# Docker для Newsroom CMS

Расширена существующая конфигурация Compose. PostgreSQL 18 и ключ его именованного тома сохранены; добавлены backend и frontend. Локальная база Windows и backend/.env не используются контейнерами.

## Хранение и безопасность данных

Основные данные: том newsroom_pg на /var/lib/postgresql — стандартный путь для PostgreSQL 18. Изображения: newsroom_uploads на /app/uploads. Оба тома получают префикс проекта Compose. Порты PostgreSQL и backend на хост не публикуются. Контейнеры не монтируют каталоги локальной PostgreSQL.

Пересоздание контейнеров выполняется docker compose up --build -d --force-recreate --wait, сохраняя именованные тома. Для чистого стенда используйте новое имя проекта, как описано в README. Удаление существующих томов не требуется.

Администратор создаётся пользователем через docker compose exec backend npm run setup:admin. Ввод скрыт и интерактивен; стандартных учётных данных нет. Демо добавляется после этого командой docker compose exec backend npm run seed:demo. Категории уже созданы миграцией.

Docker Desktop и его Linux Engine — единственные обязательные инструменты на Windows. Раздел Docker в README содержит полный путь от клонирования до демонстрации.

## Результаты проверки

- docker compose --profile test config --quiet: конфигурация корректна.
- Образы backend, frontend и тестов собраны. npm ci использовал существующие lock-файлы; сборка Vite прошла внутри Linux-образа.
- PostgreSQL, backend и frontend запущены и healthy. База мигрируется автоматически перед запуском API.
- На этой Windows порт 8080 не разрешил привязку. В локальном неотслеживаемом .env установлен HTTP_PORT=18080; сайт доступен по http://localhost:18080. Пример для клонирования сохраняет настраиваемый порт 8080.
- HTTP-проверки с хоста: /healthz, /api/health, /api/categories — 200; /my/posts и /admin/submissions возвращают русскую React-страницу. Неавторизованный /api/admin/stats и неверный вход через Nginx возвращают 401 JSON.
- docker compose --profile test run --build --rm tests: 12 из 12 тестов прошли, без пропусков. Проверены администрация, вход/выход, права, версии новостей, оригинальное авторство, комментарии, изображения, импорт, миграция старых записей и два запуска демо без перезаписи.
- Повторный запуск тестов также прошёл: каждый запуск использовал новую базу в отдельном postgres-test. После проверки временный сервис остановлен.
- Реальный Docker TTY проверен: имя и почта видны, ввод пароля не отображается, приглашение подтверждения работает. Проверка отменена до сохранения аккаунта; в базе приложения 0 пользователей, 0 статей и 9 категорий.
- Backend работает от пользователя node (UID 1000); том uploads доступен для записи. Секреты исключены из Git и build context. Тома не удалялись, локальная PostgreSQL не использовалась.

## Оставшиеся ручные шаги

В текущем рабочем каталоге корневой .env уже создан, три основных контейнера работают. Создайте свой аккаунт командой docker compose exec backend npm run setup:admin, затем при необходимости выполните docker compose exec backend npm run seed:demo. Откройте http://localhost:18080.

После клонирования на другой компьютер установите/запустите Docker Desktop, создайте .env по разделу README и выполните docker compose up --build -d. Устанавливать Node.js или PostgreSQL на Windows не нужно. Секреты текущей машины не входят в репозиторий. Скриншоты UI не проверялись; маршруты и API проверены по HTTP.
