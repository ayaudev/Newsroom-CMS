## Поведение версий

Новая отправка: PENDING_REVIEW → published либо rejected. Автор может сохранять draft. После отклонения новая отправка создаёт новую версию, сохраняя прежнее решение и оригинал. После публикации автор редактирует отдельную версию; публичная статья до одобрения не меняется. Комментарии, избранное и лайки продолжают ссылаться на тот же ID статьи.

author_user_id хранится отдельно от reviewed_by_admin_id. Для совместимости старый author_id остаётся; author_user_id генерируется из него и хранится PostgreSQL. Триггер запрещает замену author_id при обновлении. API не принимает поля автора или модератора от пользователя и сохраняет ID текущего администратора при решении.

## Команды

Из корня проекта, с существующим настроенным backend/.env:

~~~powershell
cd backend
npm ci
npm run migrate
npm run dev
~~~

Во втором терминале из корня:

~~~powershell
cd frontend
npm ci
npm run dev
~~~

Проверки из корня:

~~~powershell
cd backend
npm test
npm run test:integration
cd ../frontend
npm run build
~~~

Интеграционный запуск создаёт отдельный временный PostgreSQL на loopback и останавливает его после проверки. Рабочая база не изменяется. Для первоначальной установки без администратора после миграции выполните npm run setup:admin; для существующего аккаунта это не требуется. Интерфейс доступен на http://localhost:3000; очередь — /admin/submissions, кабинет автора — /my/posts.

- npm run build: production-сборка React прошла.
- git diff --check: ошибок нет. Поиск прежнего названия и ссылки по исходникам и сборке: 0 совпадений.

Подключённого браузера в среде нет; визуальная проверка скриншотов не выполнялась. Миграция рабочей базы не запускалась автоматически: примените её локально командой npm run migrate перед запуском обновлённого API.
